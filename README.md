# 단수달

같이 뜨개하는 픽셀아트 수달. 단수를 세면 화면 속 캐릭터가 같이 뜹니다.

## 실행

ES 모듈을 쓰기 때문에 파일을 그냥 더블클릭하면 열리지 않습니다.
로컬 서버가 필요합니다.

```
python3 serve.py
```

그다음 브라우저에서 `http://localhost:8000` 을 엽니다.
`serve.py` 는 응답에 `Cache-Control: no-store` 를 붙이는 것만 다른,
`http.server` 의 얇은 래퍼입니다. 파일을 고칠 때마다 브라우저가 옛
버전을 캐시에서 꺼내 써서 안 바뀐 것처럼 보이는 문제를 막습니다.

## 구조

```
src/pixel.js     픽셀 원시 도구 (격자, 직선, 캔버스 출력)
src/sprites.js   스프라이트 데이터와 생성기. 그림만 들어갑니다
src/states.js    상태 표. 타이밍과 전이만 들어갑니다
src/engine.js    모델 + 상태 기계 + 자세별 레이어 조립
src/main.js      DOM 연결
```

분리 기준은 **수정 이유**입니다. 그림이 마음에 안 들면 `sprites.js`,
타이밍이 어색하면 `states.js`, 규칙이 틀렸으면 `engine.js` 만 봅니다.

## 핵심 규칙

**실 총량은 보존됩니다.** `knitLength + pile + ball` 이 항상 일정합니다.

- 뜨기: 실뭉치 → 뜨개감
- 풀기: 뜨개감 → 바닥
- 감기: 바닥 → 실뭉치

목표 단수를 바꿔서 뜨개감이 줄어들 때는 바닥이 아니라 **실뭉치로**
돌아갑니다. 푼 게 아니기 때문입니다.

**뜨개감 길이는 목표 대비 비율입니다.** 픽셀 9칸으로 100단을 표현할 수
없으므로, 정확한 수치는 카운터와 진행 바가 담당합니다. 길이가 안 변하는
구간에서도 한 단 누를 때마다 새 단이 반짝여서 입력이 먹혔다는 신호를
줍니다.

## 상태 추가하기

1. `states.js` 의 `STATES` 에 항목을 추가합니다.
2. `engine.js` 의 `POSES` 에 같은 이름의 자세 함수를 만듭니다.
3. 필요한 스프라이트를 `sprites.js` 에 추가합니다.
4. 모델을 바꾸는 동작이 있으면 `engine.js` 의 `ACTIONS` 에 넣습니다.

`complete`(완성) → `showoff`(자랑) → `wearing`(착용) 순서로 구현되어
있습니다. 목표 단수에 도달하면 자동으로 `complete`·`showoff` 로
넘어가고, "입어보기" 버튼을 누르면 `wrapping`(예비 동작) 을 거쳐
`wearing` 이 됩니다. `wearing` 은 몸통 스프라이트(목·어깨선)를
건드리는 첫 상태였던 만큼 `wornScarf` 로 실루엣 자체가 달라집니다.

## 애니메이션에서 지킨 것

작업하면서 확인한 것들입니다. 나중에 프레임을 추가할 때 참고하세요.

- **회전은 축을 고정해야 합니다.** 축이 같이 움직이면 각도가 아니라
  위치가 바뀌어서 물체가 미끄러집니다.
- **회전은 양 끝이 반대로 움직입니다.** 한쪽이 내려가면 반대쪽은
  올라가야 합니다.
- **프레임마다 모양이 깨지는 건 입체 정보입니다.** 모양을 유지하려고
  고정 스프라이트로 빼면 그 물체만 화면에 납작하게 붙습니다.
- **32px에서 1px 단색 선은 어느 배경에서든 약합니다.** 밝은 심에
  어두운 테두리를 둘러야 밝은 배경과 어두운 몸통 양쪽에서 살아남습니다.
- **되감기와 되돌리기는 다릅니다.** 예비 동작 0.6초가 버그와 의도를
  가릅니다.
- **이 캐릭터는 입보다 눈과 귀로 표현합니다.** 큰 눈 + 무표정의 대비가
  매력이라 입꼬리를 올리면 오히려 약해집니다.
